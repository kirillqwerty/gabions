# SEO сайта Gabions

Подготовлено 17 сентября 2026. Продвижение рассчитано на русский язык и Беларусь. Действующий адрес — https://kirillqwerty.github.io/gabions/. Собственный домен не подключался в рамках этой работы.

## Что сделано

- 35 статических HTML-страниц, 26 индексируемых адресов в sitemap. Основное содержимое доступно без JavaScript.
- Переработаны заголовки, описания и тексты ключевых страниц. Семь новых страниц раскрывают отдельные задачи посетителя: стекло и подсветка, ландшафт, крепёж, пергоны, плюсы и минусы забора, основание, укладка эрклеза.
- Запросы распределены между коммерческими страницами и руководствами. Минск и областные центры раскрываются на одной странице заказа и доставки, без копий страниц с заменой города.
- Настроены canonical, Open Graph, социальные изображения, Organization, WebSite, WebPage, BreadcrumbList, Service для подтверждённых услуг и Article для руководств. Отзывы, рейтинги, цены и адреса филиалов не выдумываются.
- Карта сайта содержит только индексируемые канонические страницы. Служебные страницы и прежние демонстрационные карточки сохраняют noindex.
- При публикации origin и путь берутся из реальных настроек GitHub Pages. Адреса в ссылках, sitemap и JSON-LD совпадают. Проверка готовой сборки входит в Actions.
- CSS и JavaScript получают версию по содержимому для обновления браузерного кэша. Калькулятор и форма сохранены.
- Добавлены необязательные метатеги подтверждения прав Google и Яндекса через переменные сборки.

## Что известно о предложении

Заказчик подтвердил изделия из габионов, возможность заказать эрклез, подсветку и монтаж по Беларуси. Прайса нет: стоимость индивидуальна. Наличие собственного производства не подтверждено; формулировки «мы производитель» и «собственное производство» не размещены. Нужны точные сведения об изготовителе и процессе для отдельного продвижения производственных запросов.

## Как редактировать

Новые руководства и дополнительные тексты: `scripts/seo-content.mjs`. Общая структура и микроразметка: `scripts/content.mjs`. После изменения этих файлов выполните:

```powershell
npm run content
npm run check
npm test
npm run build
```

`content` обновляет семь новых страниц целиком, добавленные блоки существующих страниц, метаданные, общую микроразметку, ссылки в подвале, `docs/pages.json` и sitemap. Редактируйте такие блоки в редакционном источнике, иначе следующий запуск заменит ручные изменения. Старые содержательные блоки существующих страниц остаются в `site/`. Архивный `tools/author.py` запускать нельзя.

Пример проверки именно GitHub Pages:

```powershell
$env:SITE_ORIGIN='https://kirillqwerty.github.io'
$env:SITE_BASE_PATH='gabions'
npm run build
$env:CHECK_DIST='1'
npm run check
```

На GitHub это выполняется автоматически. Не сохраняйте проверочные коды как фиктивные значения: пока переменная не задана, тег не выводится.

## Подключение Google Search Console и Яндекс Вебмастера

1. В аккаунте владельца добавьте действующий сайт. Для Search Console используйте ресурс с префиксом URL `https://kirillqwerty.github.io/gabions/`. Проверка всего домена github.io через DNS для этого репозитория не подходит.
2. Выберите подтверждение HTML-метатегом. Скопируйте только значение `content`, без самой HTML-разметки.
3. В репозитории GitHub откройте Settings → Secrets and variables → Actions → Variables. Добавьте `GOOGLE_SITE_VERIFICATION` и `YANDEX_SITE_VERIFICATION` со значениями из соответствующих кабинетов. Это публичные коды подтверждения, SMTP-пароли сюда не относятся.
4. Запустите Deploy GitHub Pages через Actions → Run workflow. После успешной публикации завершите проверку прав в кабинетах владельца.
5. Отправьте карту сайта `https://kirillqwerty.github.io/gabions/sitemap.xml`. Проверьте главную, страницу цен, заборов и стекла инструментами проверки URL; запросите переобход доступными средствами кабинетов.
6. В Яндекс Вебмастере проверьте региональность и сведения о компании. Фактические адреса и точки обслуживания в бизнес-каталогах добавляйте только после подтверждения владельцем.

У GitHub Project Pages файл `/gabions/robots.txt` лежит в подкаталоге. Поисковые роботы ищут robots.txt у корня хоста — `https://kirillqwerty.github.io/robots.txt`. Файл этого репозитория не управляет всем хостом. Поэтому sitemap нужно отправить напрямую в кабинеты. `noindex` служебных страниц задаётся метатегами, а не запретом обхода: робот должен прочитать этот тег.

## Собственный домен

Для долгосрочного бренда разумно использовать принадлежащий заказчику домен. Это не обещание роста позиций само по себе. Сначала подтвердите владение, настройте DNS и Custom domain в Pages, затем HTTPS. Следующая сборка автоматически возьмёт origin и base_path из Pages; вручную прописывать домен во всех HTML не нужно. После переноса проверьте перенаправления старых URL, canonical, sitemap и форму, добавьте новый ресурс в поисковые кабинеты. Не указывайте неподключённый домен каноническим адресом.

## Что ещё должен предоставить владелец

- Точное юридическое наименование и подтверждение уже указанного на сайте УНП 491709206, фактический адрес при его публикации.
- Статус изготовителя, описание производства, реальные фотографии процесса, данные о материалах и покрытиях.
- Собственные фотографии выполненных объектов с разрешением на публикацию: город, размеры, состав материалов, задача и результат. Это позволит превратить демонстрационные карточки в полноценные кейсы.
- Подтверждённые отзывы клиентов с разрешением на публикацию. Текст о том, как оценивать отзывы, уже есть; он не выдаётся за отзывы заказчиков.
- При появлении прайса — дата, валюта, единица измерения, размеры и точная комплектация каждой цены. До этого сайт предлагает индивидуальную смету.

Регистрация в поисковых кабинетах, подтверждение прав и отправка sitemap не выполнены без данных владельца. Аналитические счётчики не подключены без ID и согласованной настройки. В `main.js` уже есть события `phone_click`, `messenger_click`, `calculator_complete`, `form_start` и `request_sent`; их можно использовать при подключении аналитики.

## Как оценивать результат

После индексации фиксируйте в поисковых кабинетах показы, переходы, CTR и средние позиции по каждой группе запросов, отдельно по региону и устройствам. Сопоставляйте их с обращениями. Проверяйте исключённые страницы, выбранные Google canonical и ошибки обхода. Новые тексты корректируйте по реальным запросам и вопросам клиентов; не увеличивайте плотность ключей ради формальной частоты.

Полезные следующие материалы — реальные сметы с указанным составом, кейсы заборов со стеклом, сравнение наполнителей на образцах и фото этапов монтажа. Отдельные страницы городов имеют смысл при появлении уникальных условий, объектов или филиалов, а не только нового названия города.

Время индексации и позиции зависят от поисковых систем, конкуренции и качества сайта. Эта настройка не гарантирует ТОП и не заменяет регулярную работу с коммерческим предложением и подтверждёнными результатами.
