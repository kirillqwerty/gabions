# Запуск сайта и отправки заявок

Исходные страницы — `site/`. Сборка — `npm run build`, результат — `dist/`.
`tools/author.py` — архивный генератор: не запускайте его, он перезапишет новые страницы.
Телефон, география, логотип и переключатель темы обновлены на всех 28 страницах.
Оригиналы присланных фотографий лежат в `site/assets/img/`; затемнение, кадрирование
логотипа и переход между светлыми и подсвеченными камнями выполняются CSS.

## Вариант 1: сайт и почта на одном Node.js сервере

Нужен Node.js 22.9+ и доступ сервера к SMTP (465 или 587). Из корня проекта:

```powershell
npm ci
Copy-Item .env.example .env
```

Откройте `.env` и заполните `SMTP_PASS`. По умолчанию настроен Gmail:

```dotenv
SMTP_HOST=smtp.gmail.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=gabions.by@gmail.com
SMTP_PASS=ваш_пароль_приложения
MAIL_FROM=gabions.by@gmail.com
MAIL_TO=gabions.by@gmail.com
ALLOWED_ORIGINS=https://gabions.by,https://www.gabions.by,http://localhost:3000,http://127.0.0.1:3000
```

Для Gmail нужен пароль приложения Google, обычно при включённой двухэтапной проверке:
https://support.google.com/accounts/answer/185833?hl=ru
Используйте его вместо обычного пароля аккаунта. Доступность паролей приложений зависит от настроек аккаунта.
Для SMTP-порта 587 установите `SMTP_SECURE=false`: сервер всё равно требует STARTTLS.

```powershell
npm run smtp:verify
npm run build
npm start
```

`smtp:verify` проверяет соединение и авторизацию, не отправляя письма.
Откройте http://localhost:3000/kontakty/ и отправьте свою тестовую заявку.
Проверьте получение письма, включая папку «Спам». Успех формы означает, что
SMTP принял письмо; это не гарантия попадания во «Входящие».
Без заполненных SMTP-настроек форма возвращает честную ошибку 503, поля сохраняются.

Для публичного запуска разместите приложение на Node.js-хостинге или VPS,
установите переменные окружения в панели хостинга, запустите `npm start`
под менеджером процессов. Настройте HTTPS перед приложением.
На платформе, требующей внешний bind, задайте `HOST=0.0.0.0`.
Веб-сервер отдаёт только `dist/`; `.env` и серверные файлы недоступны посетителям.
Не копируйте `.env` в `site/` или `dist/` и не добавляйте пароли в GitHub.

Пример Nginx внутри HTTPS server-блока (сертификат и домен настраиваются отдельно):

```nginx
location / {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Forwarded-Proto $scheme;
    client_max_body_size 16k;
    proxy_read_timeout 60s;
}
```

Только для такого одного доверенного прокси задайте `TRUST_PROXY=true`.
По умолчанию адрес из X-Forwarded-For не принимается на веру.

## Вариант 2: GitHub Pages + отдельный сервер почты

GitHub Pages обслуживает статические файлы и не запускает SMTP/Node.js обработчики.
Одного пароля в настройках Pages недостаточно: сначала разверните сервер выше,
например на адресе `https://api.ваш-домен/api/request`. Хостинг должен разрешать исходящий SMTP.
SMTP-пароль вводится только в окружение этого сервера.

На сервере добавьте реальный origin сайта в `ALLOWED_ORIGINS`:
для репозитория kirillqwerty/gabions это `https://kirillqwerty.github.io` (без `/gabions/`).
Если подключён домен gabions.by, используйте `https://gabions.by`.

При сборке сайта укажите публичный адрес обработчика:

```powershell
$env:SITE_ORIGIN='https://kirillqwerty.github.io'
$env:SITE_BASE_PATH='gabions'
$env:REQUEST_ENDPOINT='https://api.ВАШ-ДОМЕН/api/request'
npm run build
```

Для собственного домена задайте `SITE_ORIGIN=https://gabions.by`,
а `SITE_BASE_PATH` оставьте пустым. Публикуйте именно `dist/` как артефакт Pages.
В GitHub Actions эти три значения задаются в `env` шага сборки.
`REQUEST_ENDPOINT` — публичный URL, не секрет. В `dist/assets/js/config.js`
сборщик записывает только этот URL, никакие SMTP-переменные туда не попадают.

Для локального просмотра файлов без сборки (`npm run dev`) адрес формы берётся
из `site/assets/js/config.js`. Полная локальная проверка почты — через `npm start`.

## Поведение и защита формы

- Обязательные телефон, тема и согласие; проверка типов и ограничений на сервере.
- Письмо уходит только на серверный `MAIL_TO`; пользователь не может подменить получателя.
- Данные идут JSON POST, не в адресной строке. Нет записи полей формы в localStorage.
- Ограничение размера 16 КБ, скрытая ловушка для ботов, разрешённые origin.
- До 5 попыток за 15 минут с одного IP и 60 за час на процесс.
- Один и тот же ID успешной заявки не отправляется повторно в течение 24 часов.
- Ошибки SMTP не показывают посетителю пароли или ответы почтового провайдера.
- HTTPS сайта, TLS SMTP и проверка сертификата обязательны в публичной конфигурации.

Ограничения частоты и повторов находятся в памяти одного процесса. После перезапуска
они сбрасываются. Для нескольких реплик нужно общее хранилище и ограничения на прокси.
При разрыве соединения после приёма письма SMTP невозможно надёжно определить доставку:
повторная попытка в таком редком случае может продублировать письмо.

`npm test` проверяет HTTP-сайт, API и отправку настоящим Nodemailer на локальный
тестовый SMTP-сервер. Эти тесты не отправляют сообщения во внешнюю почту.
